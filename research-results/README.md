# Результаты небольшого корпуса асинхронной логики

Снимок от 15 октября 2026. Код и команды описаны в README проекта; связный разбор — в docs/research-report-ru.md и docs/theses-ru.md.

Проверены четыре заранее сконструированных логических сценария, каждый с buggy/fixed вариантом, при seeds 0–31. На каждом JDK получено 256 строк raw.csv: 182 PASS и 74 EXPECTED_BUG. Все 128 fixed запусков прошли инварианты. Неожиданных ошибок не было. Каждый из 256 записанных запусков повторён в свежем runtime из прочитанной с диска трассы; совпали решения, сигнатура нарушения и конечное состояние.

| Сценарий | Нарушения buggy / 32 | Нарушения fixed / 32 |
| --- | ---: | ---: |
| timeout-late-effect | 21 | 0 |
| unknown-result-retry | 21 | 0 |
| cancel-retry | 11 | 0 |
| callback-after-close | 21 | 0 |

Таблица одинакова для JDK 21.0.10 и JDK 25.0.2. В каждой группе сценарий/вариант наблюдались два уникальных пути dispatch после исключения seed из заголовка трассы. Количество запусков не означает количество независимых дефектов или разных порядков исполнения. Эти результаты не измеряют эффективность на произвольных Java-программах.

Каталоги jdk21/ и jdk25/ содержат raw.csv, summary.json, environment.json и traces/. analysis.json фиксирует независимую проверку агрегатов, размеров трасс и source fingerprint. Все 256 трасс побайтово совпали между этими двумя JDK при данном коде и seed. unit-tests.json отражает успешный набор из 34 тестов на обоих JDK; это отдельная проверка контракта, а не дополнительные строки эксперимента.

Source SHA-256: 6efa674b1321c9e6155a39806e8466833b198ce666b2170b3939969124dc1d9a. В environment.json перечислены исходные файлы, индивидуальные хеши, алгоритм агрегации и исключения. Документация и результаты исключены из fingerprint, чтобы отчёт можно было написать после эксперимента.

Для нового прогона указывать новый или пустой каталог:

```sh
sh scripts/run_corpus.sh target/corpus-local 32
```

Выбор другого JDK задаётся JAVA_BIN/JAVAC_BIN. Значение wall_nanos включает запись, дисковый ввод-вывод и replay и служит только диагностикой. Сравнительного benchmark и эксперимента на реальной инфраструктуре здесь нет.
